# ocms 事件记录规则

本文件定义「什么算事件、如何记录事件」。它是事件层（EventLayer）的客观规范。

## 一、什么算「事件」

事件 = 你与用户之间**一次有意义的对话主题**的摘要。满足以下条件之一，值得记录为一个事件：

1. **一个成形的讨论话题**：围绕某个主题展开的、有实质内容的对话（不是寒暄、不是简单问答）。
2. **产生决策/结论的对话**：这次对话里定了什么、决定了什么、得出了什么结论。
3. **跨会话延续的话题**：一个话题一次没聊完，下次继续（这类事件要跨会话延续，不能切碎）。
4. **有后续影响的话题**：这次聊的内容会影响未来的行为、决策或认知。

## 二、什么「不算」事件（不要记录）

- 寒暄、问候、闲聊（「早上好」「谢谢」）。
- 一次性的简单问答（「现在几点」「帮我查个词」）。
- 没有实质内容、没有结论、没有后续影响的短暂交互。
- 纯粹的执行指令（「帮我跑一下这个命令」），除非它背后有值得记的上下文。

**原则：宁缺毋滥。** 不确定时，不记录。

## 三、事件字段规范

记录事件时，各字段按如下填写：

| 字段 | 说明 | 要求 |
|------|------|------|
| `title` | 事件一句话标题 | 简洁、可检索，是未来检索的「摘要」字段 |
| `summary` | 事件摘要 | 这次聊了什么、结论是什么、停在哪 |
| `status` | 事件状态 | `open` / `asked` / `closed` / `dormant` |
| `parent` | 父事件 id | 大话题分组用；小话题留空 |
| `produced_decisions` | 产生的决策 id 列表 | 这次对话产出的决策，关联「事件 → 决策」 |
| `influences` | 影响的事件 id 列表 | 单向「事件 → 事件」关联 |
| `source_refs` | 原始记录指针 | 指向 `memory/YYYY-MM-DD.md` 的段落/锚文本 |

## 四、状态流转规则

```
open（进行中）
  → 话题转向，话题 B 结束后立即询问 → asked（已询问）
      ├─ 用户「继续」  → open
      ├─ 用户「不聊了」→ closed
      └─ 用户沉默      → dormant（沉底）
```

**铁律**：

1. **不主动封口**：没有「超时强制合」。`closed` 只由用户明确表态产生。
2. **立即询问（话题转向）**：话题转向结束后**当场**问，不等下次会话。问完立刻标 `asked`。
3. **下次开场询问（突然中断）**：对话突然中断，事件停在 `open`（只开未合），**下次会话开场主动询问用户是否继续**。
4. **询问一次**：标过 `asked` 后不再重复提醒。
5. **`dormant` 是合法终态**：只开不合，安静沉底，不再主动唤起，除非用户主动聊起。
6. **对话收尾时判断**：已闭环 → 整理摘要存事件；未完 → 保持 `open` 等下次继续。

## 五、关系语义（区分清楚）

| 关系 | 方向 | 语义 |
|------|------|------|
| 产生自 | 事件 → 决策 | 事件催生了决策，决策是事件的产物 |
| 影响 | 事件 → 事件 | 事件之间有作用力，但**不产出**任何东西 |
| 因果链 | 决策 → 决策 | 决策之间的「因为所以」（已有，见决策规则） |

**「影响」三铁律**：单向（时间线性）、不分强度（只关联）、多对多（只关联）。

**区分要点**：事件之间的关联用「影响」（无产出）；事件催生决策用「产生自」（有产出）。别混。

## 六、指针规范

- **只指向 daily notes**（`memory/YYYY-MM-DD.md`），不指向 `MEMORY.md`（会被改写）、不指向 transcript（会被归档）。
- **用段落标题/锚文本**定位，不用行号（抗偏移）。
- **核对优先**：用指针前先核对，对不上就降级用关键词/向量粗粒度检索。
