# ocms 收尾回顾心法

本文件讲「每一轮对话结束前，如何做一次轻量回顾，把该记的记忆补上」。它是**兜底机制**——正常情况你在对话推进中就已经随手记好了（见 `_sync_decision.skill.md` / `_sync_event.skill.md`），这一轮回顾只是查漏补缺，确保「自觉没做到」时记忆依然落盘。

## 为什么需要这一轮回顾

记忆不能只靠「对话中自觉」。人（和模型）在长对话里会专注于眼前的内容，容易忘记「顺手记一下」。所以每轮对话结束前，由 ocms 强制触发一次回顾，把这一轮产生的决策、事件、认知、品味检查一遍，漏了的补上。

**这是兜底，不是替代。** 对话推进中能记的照常记，这一轮只是保证「不丢」。

## 你要做什么

回顾刚刚这一轮对话，判断是否有值得记录但还没落盘的内容，按下面四块逐一检查：

### 1. 决策（Decision）

这一轮里，是否有「取舍、反复磨合、方向性选择、约束约定、用户明确拍板」的决策发生？

- 有 → 用 `ocms_remember` 记录（`decision` 一句话 + `rationale` 为什么 + `alternatives` 否掉了什么）。
- 如果这轮推翻了之前的某个决策 → 用 `supersedes` 关联旧决策，追加新节点（不覆盖）。
- 相关决策归入同一条 `chain`（用有意义的链名，如 `novel-setting`、`api-design`）。

判断标准见 `.ocms/rules/_sync_decision.rule.md`。

### 2. 事件（Event）

这一轮聊的话题，是否已经用 `ocms_event` 记过？

- 新话题没记 → 用 `ocms_event` 记为 OPEN（标题 + 摘要：聊了什么、结论、停在哪）。
- 已有话题有进展 → 更新摘要/状态。
- 话题聊完了 → 更新为 CLOSED。
- 产生了决策 → 在事件里用 `produced_decisions` 关联决策 id。

事件的状态流转规则见 `.ocms/skills/_sync_event.skill.md`。

### 3. 认知（Cognition）

这一轮是否沉淀了新的「客观知识、方法论、领域规律」（不依赖用户偏好）？

- 有 → 用 `write` 写到 `.ocms/cognition/<分类>.md`（自然语言 + 来源）。
- 没有 → 跳过。

### 4. 品味（Taste）

这一轮是否识别到了「审美、风格、判断倾向」（将来做类似事会不会希望保持一致）？

- 有 → 用 `write` 写到 `.ocms/taste/<分类>.md`，并维护 `taste/overview.md` 索引。
- 若这个品味来自某个决策 → 在决策的 `taste_signals` 字段带上指针，并落盘。

## 关键原则

1. **只补漏，不重复**：对话中已经记过的，不要重复记。先 `ocms_recall` / `ocms_event_list` 快速确认已有内容，再决定补什么。

2. **准确优先，宁可少记**：只记真实发生的，不脑补、不编造。这一轮没实质内容就不记——**没有任何值得记的，就什么都不做，安静结束**。

3. **不打扰用户**：这一轮回顾是收尾动作，不需要向用户汇报「我记了什么」。记完静默结束即可。**不要生成任何面向用户的新回复内容。**

4. **轻量快速**：这是兜底检查，不是长篇大论的整理。每块扫一眼，有就记、没有就过。

5. **顺序：先查后写**：动手前先 `ocms_recall` 和 `ocms_event_list` 确认现状，避免重复落盘。

## 一个注意点

回顾完成后，**不要再对用户说任何话**。这一轮回顾的唯一产出就是「把该记的记忆写进 `.ocms/`」，然后静默结束。
