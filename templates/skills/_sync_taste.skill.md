# ocms 品味维护

品味是用户（以及你自己）「喜欢、偏好什么」的取向——审美、风格、判断倾向、沟通方式、产品偏好等方面的倾向。判断标准见总纲「记忆模型」（一句话：将来做类似事，会不会希望保持一致）。

## 品味从哪里来

1. **从决策中提取**：记录决策时，若决策体现了偏好，在决策的 `taste_signals` 字段带上，并配套落到 `taste/`（见下）。

2. **从反馈中识别**：观察用户的反馈与措辞——肯定某做法（「这样才对」）、否定某做法（「不要这样」）、表达偏好（「我喜欢…」「统一用…」）、某处反复调整反映的隐含偏好。

## 品味存在哪里（两层，配套）

存在 `.ocms/taste/` 下的 md 里：

```
.ocms/taste/
├── overview.md   # 速览：各分类 + 一句话简介（索引）
└── <分类>.md     # 某角度的品味（分类名由你自然命名）
```

- **不预设分类**：分类根据实际产生的品味「自然长出来」。
- **分门别类**：按审美、风格、沟通、产品等角度拆分，别全堆一个文档。
- **分类因 Agent/用户而异**。

## 怎么记录

识别到新品味时：

1. 判断属于哪个角度——有对应分类文件则更新，没有则新建。
2. 用 `write` 写入 `.ocms/taste/<分类>.md`，自然语言描述，带上例子和来源。
3. 维护 `.ocms/taste/overview.md`，确保每个分类有一行简介索引。

**若这个品味来自某个决策**：在决策的 `taste_signals` 字段带上它（关联指针），并同步落盘到 `taste/`（详细内容）。两者配套，只做一半就是「只记了半层」。

## 品味怎么用

做事时主动参考已有品味；需速览读 `.ocms/taste/overview.md`，需细节读对应分类文件。

## 原则

- **自然沉淀**：观察真实反馈总结，不硬造。
- **准确可追溯**：带上来源。
- **克制**：不确定是否「稳定偏好」先不记，宁缺毋滥。
